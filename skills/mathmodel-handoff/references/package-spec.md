# 交接包规格 v1

用于生成、验收和更新交接包。以下路径均相对独立交接根目录；保留输入原名，通过清单记录映射。报告用 Markdown，结构表默认 UTF-8 CSV；确需多工作表时可以补充 Excel。目录按实际内容生成，不用空文件假装交付完成。

## 文件契约

| 路径 | 必需内容 |
| --- | --- |
| `HANDOFF.md` | 包版本、模式、输入范围、各小问状态、可用于写作的范围、阻塞项、阅读顺序、外部依赖、后续写作路径 |
| `manifest.csv` | file_id、包内相对路径或外部定位、原始定位、角色、SHA-256、所属版本；敏感绝对路径在对外交付前替换为可用的相对映射 |
| `reports/RESULTS_REPORT.md` | 逐小问的问题、方法、结果 ID、主要数值及单位、实际检验、结论边界；引用下列模型和证据表，不复制多份数值真源 |
| `reports/MODEL_NOTES.md` | 小问、假设及依据状态、公式、符号/单位、目标与约束、参数及来源、求解过程、代码文件与函数/行号、待队伍确认的推断 |
| `reports/EVIDENCE.csv` | evidence_id、小问、代码 file_id 与函数/位置、公式 ID、数据 ID、run_id、结果路径及键/单元格、数值/单位、拟写结论、来源类别、核验方法、状态、证据定位、论文位置（尚未写作填不适用） |
| `reports/DATA_DICTIONARY.csv` | data_id、表/工作表、字段、类型、单位、含义、缺失值约定、来源 file_id、主键或索引；未知含义明确待确认 |
| `reports/DATA_PREPARATION.md` | 输入输出映射、清洗/转换规则与实现、处理前后行列数、异常/缺失处理、单位换算、信息损失和验证证据；无需处理时说明原因 |
| `reports/VALIDATION.md` | 检查 ID、目标、实际方法/命令、预期或容差依据、观察值、证据路径、通过/失败/未验证；运行成功与模型检验分别列项 |
| `reports/GAPS.md` | 缺项 ID、关联小问/证据、影响、阻塞范围、所需材料或待跑命令、建议负责角色、完成判据；没有缺项时明确记录 |
| `reports/AI_USAGE.md` | 实际日期、可确认的工具/模型信息、辅助任务、输入输出范围、人工核验状态；未知信息不猜测，不替代赛事披露要求 |
| `runs/<run_id>/RUN.md` | 原始或本次运行、代码/数据哈希、工作目录、入口及完整命令、环境/依赖、参数、种子或未设置说明、开始/结束/耗时、退出码、超时情况、输出路径；附实际日志 |
| `code/`、`data/` | 可复制的代码与数据，注明原始副本和派生内容；外部材料用 manifest 定位，不复制无关或未授权材料 |
| `code/outputs/` | 全精度结果表及中间作图数据，每项关联 run_id；论文显示值说明舍入规则，标识符/长整数不得被数值转换破坏 |
| `figures/` | 实际图表（适用时优先矢量 PDF，必要时 PNG）及索引；每图关联图 ID、小问、数据路径、脚本/命令、run_id、坐标单位、图注要点及证据状态 |

以上报告均需覆盖对应主题；没有运行或图表时在 HANDOFF 中说明，不伪造 runs 或 figures。Notebook 需注明单元格及执行顺序，已有输出与本次执行分开。MATLAB `.mat` 或 Excel 公式转换需记录读取方式、维度/工作表、公式值来源；不能验证公式缓存或丢失精度时不得将转换标为通过。

## 验收口径

- **通过**：该项明确的检查实际完成且满足判据，并有可定位证据。队友提供的日志可证明其记录内容，不能单独证明本次已独立复现。
- **失败**：实际检查发现不符合判据，包括缺失引用文件、数据转换损坏、已确认的数值冲突等。记录观察结果及影响。
- **未验证**：检查未执行、被预算/环境阻塞或证据不足；无输出不能记为失败的实验结果，也不能记为通过。

来源类别独立记录为“队友提供／本次复现／本次派生”，不要用来源替代状态。仅阅读代码的结论与数值复现分别核验。缺失项目按小问列明，不以总体标签掩盖局部问题。

总体分为“可交接／部分交接／阻塞”：各小问所需材料完整且关键检查通过才可交接；存在可用部分及局部缺项为部分交接；无任何足够证据支持写作时为阻塞。可交接不表示论文已经合规或模型绝对正确。HANDOFF 应列出采用该总体状态的具体原因。

按模型需要选择检验，避免为了凑齐清单运行无关实验：预测关注划分泄漏、基线及误差；优化关注可行性、求解状态及可获得的最优性差距；评价关注权重来源与排序稳定性；随机仿真关注重复结果及波动。未实施的必要检验进入 GAPS。模型动机和假设的推断即使数值复现通过仍须保留待确认标签。

交付前实际核查：清单路径与哈希、证据引用的结果键/单元格、结果与模型单位、数据转换前后计数、图表源数据与显示值、预算日志、所有阻塞项与总体状态的一致性。验收既有包时追加验收记录，不覆盖原打包者记录。

## 使用场景检查

以下场景用于检视流程，不表示本仓库已运行真实赛题。

1. Python 入口可运行、数据齐全：生成独立运行记录，逐项检验后允许对应小问进入写作；不是仅凭退出码通过全部验收。
2. MATLAB 环境缺失且只有已有结果：保留已有结果来源，数值复现为未验证，给出原语言待跑命令及环境需求，不改写成 Python 冒充复现。
3. 新旧结果不同或只有截图：保留两套证据，明确冲突/未知项；无原始数据的图不能附上猜测出的精确表格。
4. 已耗时 880 秒但下一任务预计需 120 秒：不启动该任务，交付部分包和待跑命令；预算不重置。
5. 更新一小问数据：新包标记相应公式、结果、图及论文引用待复核，其他小问保留已验证记录与原始版本来源。

## 论文可用证据的补充要求

2026-09-10 补充，保持 v1 既有路径和字段兼容；内容写入现有报告，不增加无用途空文件。[来源与推导](cumcm-case-lessons.md) 区分案例观察和本项目建议。

1. **题目要求覆盖**：在 RESULTS_REPORT 中按小问列出要求的输出、范围、时间点、对象和精度，并映射到实际结果键、附件表格或缺项。题目给定的结果模板保留工作表名、行列标签和指定精度；不能仅交几张精选图代替完整结果。
2. **可比较情景**：在 MODEL_NOTES 标明情景 ID、变化的假设/参数与保持一致的条件，RESULTS_REPORT 用同一时间范围、单位和统计口径比较。比较“提升”时给出基准与计算方法，零基准时不用失真的百分比。随机结果标明单次、均值或分位数及重复次数；不同风险目标不能仅凭目标数值大小判优。
3. **实现到公式的细节**：按模型实际需要记录索引/时间起点、坐标轴方向、角度制、分段条件、边界条件与代码分支。数值求根、搜索或离散近似记录区间、步长、收敛判据与容差。若缺少对应核验，不把高显示精度当作高计算准确度。
4. **最优值与决策明细**：优化结果同时定位决策变量表、目标值、求解状态及约束残差/违反量。时间、地块、产品等维度说明轴标签与单位。启发式算法只能按实际证据描述找到的方案，不能把“本次最好”无依据写成“全局最优”。
5. **必要对照与稳定性**：在 VALIDATION 中说明选择某项基线、灵敏度或边界检验的理由，记录输入范围、扰动方式、保持条件、指标和观察。已有证据足够则引用，缺失且预算不足则进入 GAPS，不自动增加大规模实验。
6. **写作可引用的事实**：在 RESULTS_REPORT 末尾列摘要候选事实：任务、方法、关键结果 ID、数值真源、单位、适用情景、核验状态与限制。只列事实要点，不起草摘要；让摘要、正文表格与附录共享同一数值来源。图表索引注明它支持的结论、维度/聚合规则和异常值处理，不以视觉效果代替数据解释。

## 国赛提交准备

在 HANDOFF 中增加“参赛支撑材料准备”部分，仅适用国赛；具体规则通过 [来源说明](cumcm-case-lessons.md) 路由到当年官方要求。

- 将内部 manifest 映射到拟提交文件及论文附录位置，覆盖实际使用的源程序、Excel/SPSS 等交互操作、必要的自查数据与中间结果；无程序/无支撑材料的说明必须符合实际。
- 原始记录留在内部包；拟提交副本检查路径、文件名、内容、图像和可检查的文档属性中的身份信息。转换或匿名化后重新检查相对路径及运行方式，不能删除必要代码来缩小文件。
- 列明匿名检查、文件列表一致性、包大小、压缩格式及 AI 披露材料的检查状态。尚未生成最终论文/压缩包时标记未验证；本阶段默认只给出准备清单和映射，实际生成参赛副本按用户任务范围执行，不自动提交。
- 交接采用 SHA-256 追溯内部版本；实际平台校验方式另按当年通知处理。引用资料保留作者/机构、标题、年份、URL/DOI 与支持的具体主张，不能把案例来源自动加入论文参考文献却未实际使用。
