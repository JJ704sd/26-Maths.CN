## 使用原则

AI 可辅助，核心建模和分析须由队伍主导；对 AI 参与内容逐项人工核验。故意隐瞒、虚假声明、未经必要人工核验直接提交 AI 核心成果会导致取消评奖资格。不要以“降 AI 率”为目标改写，也不要删除记录或编造人工修改记录。

比赛期间不得与队外人员讨论赛题，也不得在 GitHub 等交流平台浏览、发布或讨论与赛题相关内容。赛前安装工具不等于赛中可以浏览赛题解答。引用公开资料须在正文标注并列入参考文献，不可大篇幅照抄。

## 你的职责与队内交接

论文手要能解释每个公式、每张图和每项结论。不要只接收模型名称与截图：每道题要求建模手、代码手提供以下证据。

| 交接项 | 验收标准 |
| --- | --- |
| 问题与输出 | 明确回答题目哪一问，结果单位是什么 |
| 假设与理由 | 说明依据、适用范围和失效条件 |
| 模型 | 变量、目标、约束、参数来源齐全 |
| 实验 | 数据版本、清洗规则、运行入口和环境明确 |
| 结果 | 数值能定位到文件或代码输出，不凭截图手抄 |
| 检验 | 基线、误差或适用的验证方法；没有做的实验不写成已完成 |
| 局限 | 指出哪些结论不能由现有证据推出 |

写作顺序建议：问题清单 → 假设与符号 → 模型与求解 → 结果与验证 → 局限 → 摘要。摘要最后写，用“任务—方法—关键数值—适用结论”组织，删掉无证据的“显著提高”“精确预测”等判断。

## 提交检查

- A4；四边页边距至少 2.5 cm；摘要含标题和关键词原则上不超过一页，从摘要开始页脚居中编号为 1；无目录，正文不超过 30 页。
- 纸质版前置承诺书、编号页；电子版不含这两页，第一页为摘要。附录包含支撑材料清单和全部完整可运行代码，包括相关软件交互命令。
- 电子论文为单独 PDF 或 Word，建议 PDF，不压缩且不超过 20 MB。支撑材料用 WinRAR 打包为 ZIP/RAR，不超过 20 MB；包含必要代码、自查数据和中间结果。
- 摘要、正文、附录及支撑材料不得泄露参赛者、学校、赛区身份。检查图像、路径和文件内容；保留原始工作记录，制作匿名提交副本。
- 每个核心数值回查运行结果；单位、精度、符号、图表与文中引用一致；参考文献逐条核对真实来源。
- 参考文献前放置 AI 工具使用声明；使用 AI 时在支撑材料加入规定名称的详情 PDF。详见记录模板。不能把尚未填好的模板作为提交材料。

## 七天赛前训练（建议安排，不是官方要求）

1. 选往年赛题，拆出所有问题与交付物，独立写一页结构提纲。
2. 根据队友真实模型笔记写假设、符号、目标与约束；让队友检查含义是否改变。
3. 用已有可复现结果写一节结果分析，每个数值标记其证据文件。
4. 练习模型检验：解释一个误差指标、一个基线比较和一个局限；不虚构实验。
5. 压缩摘要到一页，保留主要方法、核心结果及适用范围。
6. 完成一次全文交叉核对：问题是否全部回答，符号、图表、引用是否一致。
7. 模拟提交：独立重跑程序、核验结果、整理附录与 AI 记录，逐项检查格式。

每次训练评分：题目覆盖、推理可理解性、证据可追溯性、表达准确性、格式完成度各 0–2 分。这是自评量表，不是官方评奖标准。

## 可直接使用的论文审阅提示

> 你是我的数模论文审阅助手。只依据我提供的题目、模型笔记、原始结果和草稿审阅。按“问题位置—缺陷—证据—修改建议”输出；区分事实错误、论证缺口和表达问题。不得编造数据、实验、引用或模型创新；材料不足时列出缺失证据。不要替我选择核心模型，不以 AI 检测分数为目标。对润色前后数学含义的变化单独标记，供我核验。本次使用情况需记入 AI 记录。

将资料复制给 AI 前确认它适合交给所用服务处理，避免包含个人身份、密钥或非公开第三方资料。
